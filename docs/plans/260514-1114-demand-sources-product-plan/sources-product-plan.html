Demand Center / Sources / Product + BA Plan

Sources as the Demand Source Registry and Source Quality Engine

Sources gom, chuẩn hóa và đánh giá toàn bộ nguồn tạo demand cho seller/factory. Module này giúp operator biết demand đến từ đâu, nguồn nào tạo lead/RFQ thật, SKU nào có tín hiệu tốt, campaign nào đang kéo demand thật, và nguồn nào đáng tiếp tục đầu tư.

Product position Registry + engine

Không chỉ là channel list hay traffic dashboard.

Primary route /demand/sources

Existing route is already wired in PrimeOS.

MVP data Derived first

Use socialStreams, campaigns, leads, RFQs before backend contracts.

Operating output Scale / fix / pause

Every source needs an owner, reason, and next move.

1. Scope Challenge

YAGNI/KISS check: build the decision workspace first; avoid turning Sources into a full ad manager, CRM, BI attribution suite, or ingestion admin console.

Scope locked Hard plan

What Sources must own

  • Ghi nhận nguồn demand: marketplace, social, ads, partner, manual import.
  • Chuẩn hóa source data thành registry có owner, market, SKU/category, campaign links.
  • Đo chất lượng nguồn bằng lead/RFQ quality, conversion, duplicate, freshness, buyer fit.
  • Đưa ra next action: scale, test, fix, pause, review, route leads/RFQs.
  • Giữ source lineage khi handoff qua Campaigns, Leads/RFQs, Customer/CRM, Finance, Intelligence.

What Sources must not own

  • Không xử lý toàn bộ CRM hoặc account/customer lifecycle.
  • Không quyết định giá bán, fulfillment, finance ledger, funding approval, hay campaign budget approval.
  • Không mutate product master, order truth, quote truth, customer truth từ Sources page.
  • Không claim final attribution/ROI nếu chưa có Intelligence readback model rõ ràng.
  • Không hiển thị vanity metrics nếu metric đó không hỗ trợ decision hoặc handoff.

4. Domain Model

The core chain is Source -> Signal -> Lead/RFQ -> Opportunity. Sources owns upstream origin quality and lineage, not downstream source-of-truth records.

Layer 1 Source

Where demand originates: marketplace, social, ads, partner, manual import.

Layer 2 Signal

Click, message, form, comment, inquiry, trend, import row, referral event.

Layer 3 Lead / RFQ

Qualified buyer intent with SKU, customer, market, SLA, value context.

Layer 4 Opportunity

Commercial opportunity ready for CRM, campaign, finance, or COS handoff.

Module taxonomy

  • Marketplace Source: Amazon, Rakuten, Shopee, TikTok Shop, other marketplaces.
  • Social Source: Facebook, Instagram, TikTok, YouTube, LINE/community.
  • Ads Source: Google Ads, Meta Ads, TikTok Ads, marketplace ads, sponsored campaign.
  • Partner Source: distributor, agency, affiliate, KOL/creator, business partner.
  • Manual Import: CSV, sales team input, event list, offline contact, legacy lead data.

Entity set

5. Business Rules and Boundaries

These are the rules that make Sources operational instead of becoming another passive dashboard.

Rule Why it matters MVP enforcement
Một lead phải có source gốc. Without origin, attribution and quality learning break. Show missing-source warning and mapping rule prompt.
Một source phải có owner. Source insights need accountable action. Owner column required; ownerless sources go to needs review.
Duplicate rate cao phải bị flag. Protect lead/RFQ quality from noisy imports or spam. Add duplicate risk as score penalty and review reason.
RFQ quality cao nên recommend tăng đầu tư. Operators need investment decision support. Scale recommendation requires RFQ rate, buyer fit, SKU readiness, finance guardrail.
SKU hết hàng phải cảnh báo. A strong source can become harmful if fulfillment cannot support demand. Block scale CTA and route to COS/Product.
Manual import phải có batch log. Hand-entered demand needs traceability. Every manual row points to SourceImportBatch and import owner.

6. UI / UX Plan

Enterprise SaaS direction: fewer explanatory paragraphs, more ranked operating views, visual source quality, and fast links into product functions.

Sources Overview

  • Top answer card: best source, worst source, and next operating action.
  • KPI strip: active sources, top performing source, leads, RFQs, avg quality, sources needing review.
  • Quality matrix and source funnel above the fold.
  • Quick links to Campaigns, Leads/RFQs, MDEC, Product/SKU, Finance.

Source List

  • List-first layout with expandable rows or detail drawer.
  • Columns: source, type, owner, market, leads, RFQs, quality, duplicate rate, status, next action.
  • Row actions: view detail, route leads, create campaign, fix content, suppress source.
  • Filters: type, status, owner, market, SKU/category, campaign, review needed.

Source Detail

  • Basic info, owner, market, connected channel, mapping rules.
  • Performance: signal, lead/RFQ, conversion, score, duplicate, cost per qualified lead.
  • Linked campaigns and SKU/category signals.
  • Recent signals, attribution timeline, import batch log, recommended actions.

8. Operating Workflows

Each workflow should end with an explicit owner, target workspace, audit note, and reversible handoff.

Workflow Trigger Steps Output
Connect source New source or channel discovered. Select type, owner, market, connection mode, linked SKU/category, mapping rule. DemandSource active or needs_review.
Manual CSV import Sales/event/offline lead list. Upload batch, map fields, dedupe, assign source owner, preview errors, commit import. SourceImportBatch with traceable rows.
Qualify signal to lead/RFQ Signal has buyer fit and SKU intent. Open signal detail, confirm lead/RFQ candidate, attach source attribution, route to Leads/RFQs. Lead/RFQ handoff package.
Attribution override First/last-touch is wrong or missing. Review timeline, choose source, add reason, save manual override. Auditable SourceAttribution update.
Suppress weak source Duplicate, stale, low quality, blocked SKU, poor buyer fit. Open source, inspect reasons, choose pause/suppress, notify owner, set review date. Status paused with recovery rule.
Scale source Quality score and RFQ quality are strong. Check inventory, finance, customer suppression; then create campaign or resource recommendation. Campaign/Finance/Product handoff, not direct budget mutation.

9. Data Contracts

MVP should implement a derived read model first, then evolve toward persisted source registry and API contracts.

type SourceType =
  | 'marketplace'
  | 'social'
  | 'ads'
  | 'partner'
  | 'manual';

type SourceStatus =
  | 'active'
  | 'inactive'
  | 'needs_review'
  | 'suppressed';

interface DemandSource {
  id: string;
  name: string;
  type: SourceType;
  status: SourceStatus;
  ownerId: string;
  ownerLabel: string;
  market: string;
  connectedChannel?: string;
  linkedCampaignIds: string[];
  linkedSkuIds: string[];
  linkedCategoryIds: string[];
  qualityScore: number;
  leadCount: number;
  rfqCount: number;
  conversionRate: number;
  duplicateRate: number;
  costPerQualifiedLead?: number;
  lastSyncAt: string;
  nextAction: SourceNextAction;
}
interface SourceAttribution {
  id: string;
  leadId?: string;
  rfqId?: string;
  opportunityId?: string;
  firstSourceId?: string;
  lastSourceId?: string;
  touchpoints: Array<{
    sourceId: string;
    campaignId?: string;
    occurredAt: string;
    confidence: number;
    eventType: 'click' | 'message' | 'form' | 'comment' | 'inquiry' | 'import';
  }>;
  manualOverrideSourceId?: string;
  overrideReason?: string;
}

interface SourceQualityScore {
  sourceId: string;
  score: number;
  label: 'scale' | 'test' | 'fix' | 'pause' | 'review';
  factors: {
    leadVolume: number;
    rfqVolume: number;
    responseQuality: number;
    buyerFit: number;
    skuRelevance: number;
    duplicatePenalty: number;
    freshnessPenalty: number;
  };
  reasons: string[];
  blockers: string[];
}
MVP read model recommendation

Create helper functions such as buildDemandSources(snapshot), scoreDemandSource(source), and getSourceRecommendedAction(source). Derive initial rows from socialStreams, campaigns, leads, and rfqs; only persist canonical entities after taxonomy and thresholds are approved.

11. Acceptance Criteria

Definition of done for the eventual implementation.

Product acceptance

  • Page clearly communicates Sources as demand origin quality and action routing.
  • Operator can identify top source, weak source, and next action in under 30 seconds.
  • Every source has status, reason, owner or owner placeholder, and target action.
  • Lead/RFQ lineage preserves source and campaign context.
  • Weak/risky sources are visible before scale recommendations.
  • Charts support decisions: quality, funnel, type mix, SKU signal, attribution.

Engineering acceptance

  • Derived model is typed and isolated from page presentation.
  • No CRM, order, product, finance, or external platform mutation occurs from Sources MVP.
  • Empty/missing data states render without fabricated numbers.
  • Routes and navigation remain stable: /demand/sources remains canonical.
  • Responsive layout avoids cramped card grids on narrow screens.
  • Build/lint/test pass, or known failures are documented with exact cause.
