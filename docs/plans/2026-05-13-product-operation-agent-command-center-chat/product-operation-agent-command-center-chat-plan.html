Approval Plan · Product Operation Agent

Command Center thành AI Agent Chat Command Interface

Chuyển Command Center từ dashboard-first sang chat-first: operator ra lệnh bằng ngôn ngữ tự nhiên, agent trả lời bằng evidence/action preview, rồi handoff sang Kanban, Agent Queue hoặc Audit. Phase này vẫn giữ boundary an toàn: chat chỉ prepare, route, summarize, queue approval; chưa mutate source-of-record.

Route: /intelligence/product-operation-agent?view=command No live LLM in MVP No destructive action from chat Research: Lazyweb + web references

Research Decision

1
Chat là command surface chính

Composer + transcript phải nằm above the fold. Metrics chuyển thành context rail để không lấn luồng ra lệnh.

2
Agent output phải có governance

Mỗi câu trả lời cần owner, source route, evidence, policy state, approval requirement, và next safe action.

3
Execution đi qua Queue/Audit

Chat không đóng vai source of truth. Action quan trọng phải queue approval hoặc mở route nguồn.

Success Criteria

  • Command Center opens as a chat-led operator interface, not a metrics dashboard.
  • Agent responses are grounded in existing Product Operation Agent cards, proposals, source routes, evidence, and policy checks.
  • Every suggested action has visible command status, source context, approval requirement, and audit implication.
  • Operators can move from chat output to Kanban card, Agent Queue proposal, or source suite route without losing context.
  • No destructive or source-of-record mutation is introduced from chat in this phase.
  • Existing Kanban, Queue, Audit, navigation, and seed-data tests continue to pass.

Scope

In Scope

  • Redesign only Product Operation Agent Command Center view.
  • Add chat transcript, command composer, suggested prompts, command status rows, context cards, and action preview panel.
  • Use existing OperatingCard, OperatingAgentProposal, audit seed structures.
  • Provide deterministic mock chat behavior for approval and QA.
  • Preserve Product Operation Agent route, tabs, Kanban, Queue, Audit, source links.

Out Of Scope

  • Live LLM integration.
  • Backend persistence for chat sessions.
  • Executing destructive actions from chat.
  • Replacing Operating Kanban, Agent Queue, or Audit surfaces.
  • New navigation route beyond existing ?view=command.

Phased Implementation Plan

Phase 0

Approval Gate

Confirm chat-first direction, non-destructive operator boundary, and no IA changes.

  • Approve research direction.
  • Approve deterministic MVP behavior.
  • Approve safe CTA language: prepare, queue approval, open source, summarize.
Phase 1

Data Contract

Map chat model to existing Product Operation Agent data.

  • Define message types: operator prompt, agent answer, command status, evidence reference, action preview.
  • Map prompt outputs to cards, proposals, routes, policy checks.
  • Add minimal seed data only if needed for realistic transcript examples.
Phase 2

Command Center UI Build

Replace dashboard-first layout with a split command surface.

  • Transcript and composer as center panel.
  • Operating context as left rail or top compact rail.
  • Action preview as right rail on desktop, collapsible section on mobile.
  • Prompt chips: approvals, blocked work, inventory risk packet, audit summary.
Phase 3

Governance And Accessibility

Make trust boundaries and states clear.

  • States: ready, needs approval, blocked, executed/mock, audit-only.
  • No irreversible CTA wording.
  • Keyboard flow, focus states, contrast, responsive layout.
Phase 4

Test And Approval Package

Ship evidence for review before deeper agent integration.

  • Unit/component coverage for prompts and response rendering.
  • Existing Product Operation Agent tests continue passing.
  • Lint/build pass.
  • Browser smoke desktop and mobile for ?view=command.

Risks And Mitigations

Risk Impact Mitigation Escalation Trigger
Chat implies real autonomous execution Trust and boundary confusion Use prepare/route/approval language; avoid destructive CTA labels Any stakeholder reads a command as live mutation
Scope expands into live LLM or persistence Timeline and QA confidence drop Keep MVP deterministic; capture live-agent work as later phase Request requires backend, auth, streaming, saved history
Chat disconnects from Kanban/Queue/Audit Breaks governed operating model Every answer links to card, proposal, route, or audit state Response appears without evidence/source/owner/action status
Mobile layout becomes unusable Approval failure in responsive QA Stack transcript first, sticky composer, collapsible context/action panels Composer, buttons, or evidence cards overlap below tablet width

Test Plan

  • Unit/component: Command Center renders transcript, suggested prompts, source-linked responses, and action previews.
  • Regression: View switching, Product Settings navigation, Kanban movement, Queue, Audit remain intact.
  • Build: Run frontend lint/build commands used by the repo.
  • Browser smoke: Verify ?view=command on desktop and mobile; check no overlap, broken links, or inaccessible controls.
  • Governance QA: Every command response has owner, evidence, source route, approval state, and non-destructive CTA language.

Approval Checklist

  3. Approve non-destructive operator boundary.
  4. Approve implementation limited to Product Operation Agent Command view.
  5. Approve test plan before code starts.
