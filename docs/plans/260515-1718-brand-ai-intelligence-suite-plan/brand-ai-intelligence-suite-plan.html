01. Product Positioning

Branding Agent là foundation product trong Intelligence Suite, nằm trước Consulting Agent, Signals Board và Launch Decisions.

Recommended scope
1

Product promise

Nhập business context một lần, PrimeOS tạo brand intelligence foundation có thể dùng lại cho consulting, signal tracking, launch và campaign decisions.

Difference vs Brand Foundation

Brand Foundation tạo tài liệu thương hiệu. Branding Agent tạo intelligence package có evidence, assumptions, decision thresholds và agent-ready schema.

3

Brand knowledge đang nằm rải rác trong deck, notes, website, sales calls và founder memory. AI agents thiếu context chuẩn để tư vấn đúng.

05. Data Model

Dữ liệu phải đủ cho versioning, audit, permissions và downstream agent context. Không chỉ lưu markdown.

BrandAIProject { id: string workspaceId: string brandId: string goal: 'foundation' | 'audit' | 'repositioning' | 'launch' | 'messaging' | 'consulting_onboarding' status: 'draft' | 'generating' | 'needs_review' | 'ready' | 'blocked' | 'archived' confidence: number evidenceCoverage: number sourceIds: string[] currentVersionId: string createdBy: string updatedAt: string } BrandAIAnswerSession { id: string projectId: string questionSetId: string answers: Answer[] completionRate: number submittedAt?: string } BrandAIPackageVersion { id: string projectId: string sourceSessionId: string status: 'draft' | 'reviewed' | 'locked' documents: GeneratedDocument[] facts: Claim[] assumptions: Claim[] unknowns: Claim[] signalWatchlist: Signal[] agentContextJson: object }

Must separate

Facts, assumptions, inferences và unknowns phải tách riêng để tránh AI hallucinate thành strategy.

Must version

Regenerate không ghi đè package đã reviewed/locked. Mọi package có source session và diff.

Must audit

Handoff sang Demand/Launch/Consulting phải ghi usage, version, actor và timestamp.

06. PrimeOS Integration

Branding Agent là context provider. Output phải dùng được trong các workflow khác, không bị kẹt trong trang detail.

C

Consulting Agent

Brief agent bằng brand context, positioning, strategy constraints và client assumptions.

S

Signals Board

Tạo signal watchlist cho market, demand, competitor, customer behavior.

L

Launch Decisions

Chuyển package thành launch memo, guardrails và decision thresholds.

D

Demand

Handoff audience-message fit, campaign themes và demand experiment backlog.

Integration rule: downstream workflows phải cho chọn `latest version` hoặc một `pinned version`. Nếu package bị archive hoặc evidence stale, UI phải cảnh báo trước khi dùng.

09. Risks & Product Decisions

Những quyết định này nên chốt trước khi cook implementation để tránh build sai phạm vi.

Key risks

  • Output chung chung nếu intake thiếu strategic interview.
  • AI hallucinate nếu không tách fact / assumption / unknown.
  • Package lỗi thời nếu thiếu versioning và source freshness.
  • Downstream agents dùng nhầm package nếu không có pinned version.
  • External share có thể lộ Customer/Finance evidence nếu permission không rõ.

Open decisions

  • Một package theo brand, brand-market, hay brand-market-category?
  • MVP có hỗ trợ upload file ngay không, hay chỉ URL + text?
  • Auto-handoff sang Demand hay bắt buộc human review?
  • Nguồn nào là mandatory để confidence vượt ngưỡng?
  • Export/share external có được bật trong MVP không?
